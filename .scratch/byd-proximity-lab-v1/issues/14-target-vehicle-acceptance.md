# 14 验收目标车和目标手机上的接近检测

Type: task
Status: ready-for-human
Blocked by: 12
User stories: 4, 5, 6, 8, 12, 26, 27, 28, 29, 31, 34

## 任务

在比亚迪宋 PLUS DM-i 2024 荣耀版和拟使用的 Android 手机上验证锁车、休眠、区分本车和锁屏接近。先确认有没有足够的已关联数据，再判断当前参数的模拟触发表现。

**交付物** 目标车型与目标手机的实测结论，附关联证据、会话记录和未通过条件。软件和台架验收分别记录。

## 设备与记录方式

- 记录车辆车型/版本、是否锁车及静置时间、手机型号与 Android/ROM、权限和电源设置、App/算法/触发规则版本、算法配置、手机放置方式、环境和 Session 标识。涉及日常钥匙在场或离场时只记录试验条件。
- 先做前台醒车或独立可见广播对照，确认手机扫描链正常。分别记录扫描不可用、手机未观察到目标、候选可见而身份未确认、以及已成功关联但信号弱。零回调只说明该环境下未收到样本。
- 使用 V1 最少权限的实际发版配置，记录 `neverForLocation` 下的目标广播可见性。若怀疑目标广告被过滤，记录可观测的对照和差异，是否调整权限单独讨论。未经现场确认的地址轮换特征不写入识别规则。
- 实车试验使用 App 的只读扫描和本地模拟事件。安排标记者记录预期触发位置，定时/锁屏试验可分开进行。用一组 Session 调整参数，再用独立 Session 记录当前配置的表现。

## 操作与验收记录

| 类别 | 操作 | 采集与判读 |
| --- | --- | --- |
| 锁车与休眠 | 在醒车、刚锁车、数个预先记录的静置时段以及重新可观测后扫描 | 记录各阶段可见性、观测间隔、最长可观测空窗、地址或载荷变化 |
| 本车关联 | 在有相邻同款或同品牌车的环境复验，观察新地址、相近信号与身份不确定情形 | 记录能否唯一关联、依据、误关联或身份不确定。无法取得可信特征时核对原绑定不变、事件被抑制 |
| 真实接近 | 从不同方向接近，覆盖手持和口袋、遮挡、停留、走远后折返 | 记录每次是否在 `NEAR` 之前观测到有效 `FAR`、模拟事件数量与时点。仅近端可见造成的漏触发另记成因 |
| 无需触发 | 记录相邻车位路过、车边停留、近端开始、停扫恢复等有参考标签的试验 | 记录误触发、重复、`UNKNOWN` 原因和恢复后的表现 |

## 判读顺序

1. **先确认对照。** 对照广播也没有被收到，先记录扫描或试验条件待确认，车辆广播可见性暂不能判定。对照正常且目标未见，记录该场景下手机未收到目标观测。
2. **再确认属于本车。** 观察到候选但无法唯一关联时，记录身份不确定和候选冲突。该场景不能作为车型接近验收通过的证据。
3. **检查 `FAR` 证据。** 唯一关联已建立且只收到近端帧时，记录零补触发符合策略。若这是一条有完整评分覆盖的正样本，同时记录因缺少前置观测而漏触发。有可信 `FAR` 时再核对后续 `NEAR` 和事件。
4. **分别核对事件与锁屏通知。** `ENTERED_RANGE` 已写入而锁屏通知未呈现时，两列分别记有事件、通知未呈现。保留通知设置和观察时段。

## 完成条件

- 在 Answer 分开给出车型/手机是否通过、哪些场景失败及哪些待测。无法稳定识别本车、休眠后缺少足够 `FAR` 或手机采集不连续时，把现象和对应 Session 写清，目标车型验收保留不通过或待测结论。
- 汇总已有评分的正负样本和独立样本结果，注明触发时间窗与配置。缺少量化依据时保留测量数据和需继续采集的场景，不推定准确率、延迟或耗电上限。软件和工具验收仍各自记录。
